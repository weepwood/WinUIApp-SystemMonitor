# System Monitor · WinUI 3

基于 **WinUI 3 + .NET 8** 的 Windows 本地系统监控工具，采用 **Fluent 2** 设计语言、Mica 窗口材质与自适应布局。

## 下载与运行

从 **[最新正式版](https://github.com/weepwood/WinUIApp-SystemMonitor/releases/latest)** 下载 `SystemMonitor-vX.Y.Z-win-x64-setup.exe`。这是 **WinUI 3 完整版的安装程序**：双击安装后，从开始菜单打开 **System Monitor**。安装到当前用户目录，无需管理员权限，也不必单独安装 .NET 或 Windows App SDK。可在 Windows「已安装的应用」中卸载。仅发布 Windows x64 安装程序，不再提供单文件轻量客户端。

支持 Windows 10 1809 及以上；Mica 效果取决于 Windows 版本与透明效果等系统设置，不支持时仍保留 Fluent 布局。可用 `Get-FileHash <安装程序路径> -Algorithm SHA256` 对照发布页的 `.sha256` 文件。

## 界面设计

- **Fluent 2 设计规范**：统一的卡片、字体层级、间距与圆角；所有颜色取自系统语义画刷，自动适配浅色 / 深色主题与高对比度回退。
- **指标色板**：CPU（蓝）、内存（薄荷绿）、磁盘（琥珀）、网络（薰衣草）各有独立的强调色与 10% 透明度底色，浅色与深色主题分别调校对比度。
- **窗口材质**：Mica、亚克力或纯色三种材质可切换；Windows 10 上 Mica 自动回退为亚克力，材质不可用时退回纯色以保证可读性。
- **自定义标题栏**：48 px 标题区与应用标识，窗口控件透明；标题栏下方的紧凑命令条常驻显示监测状态、刷新间隔、最近更新时间和快捷操作。
- **响应式布局**：总览的四张指标卡在 1200 / 780 像素断点间自动切换 4 列、2 列与单列；内存、系统信息等双栏卡片在 900 像素以下改为单列。
- **微交互与可访问性**：按钮提供工具提示与 AutomationProperties 名称，数值可选中复制，快捷键 F5 / Ctrl+P / Ctrl+, 覆盖常用操作。

## 页面

- **总览**：四张指标卡并排显示 CPU 与内存使用率（含迷你趋势图）、存储总占用与网络下载速率；下方为设备概况、驱动器容量与网络适配器列表。
- **CPU**：平滑趋势图与平均 / 峰值 / 当前频率磁贴、每核心使用率网格、处理器规格。
- **内存**：圆角仪表盘、内存明细（已用 / 可用 / 已提交 / 缓存）、使用率趋势与内核内存池。
- **磁盘**：存储总览与总占用进度，每块驱动器的容量、剩余空间与实时读写速率。
- **网络**：实时吞吐汇总，每块网卡的连接状态、地址、MAC 与上下行速率。
- **进程**：完整进程列表，支持按名称筛选、按内存 / CPU / 名称 / PID 排序，选中后在下方查看 PID、CPU、内存占比、线程、句柄、优先级、启动时间与可执行文件路径，并可一键复制当前列表。
- **系统信息**：操作系统、固件、主板、显卡与显卡驱动、电源状态、进程 / 线程 / 句柄统计，以及带占比条的内存占用前 5 进程。
- **电源**：电池电量环、供电方式、充电状态与电量水平；台式机等无电池设备显示「无电池」。
- **复制摘要**：首次采样完成后，可复制带更新时间的监测数据。摘要取自界面上最近一次更新的值，不重新查询硬件，不包含 IP 地址。

## 开发与构建

系统要求：Windows 10 1809 及以上，Visual Studio 2022（安装 Windows 应用开发相关工作负载）、.NET 8 SDK。项目默认平台为 x64。

```powershell
dotnet restore WinUIApp.csproj -p:Platform=x64 -p:RuntimeIdentifier=win-x64
dotnet build WinUIApp.csproj -c Debug -p:Platform=x64 -p:RuntimeIdentifier=win-x64
```

发布：在 Actions → Windows Build → Run workflow 选择分支并输入新标签（如 `v1.3.0`）。Windows runner 自包含发布 WinUI 项目，通过 Inno Setup 6 生成安装程序，并在临时目录验证安装、启动与卸载。验证通过后发布安装程序与 SHA-256 文件。标签留空则仅编译。

从 `WinUIApp.slnx` 也可以在 Visual Studio 中打开、编译并运行。CI 使用 GitHub Actions Windows runner 检查 x64 Debug 构建。

## 采集与资源使用

- CPU、内存、网络与电源状态每次监测刷新都会采样；磁盘、静态系统信息与进程列表按「进程与慢速指标刷新间隔」（默认 5 秒）采集。
- 进程 CPU 占用率来自两次采样之间 `TotalProcessorTime` 的差值除以经过时间与逻辑处理器数量，因此首次采样显示为 0%。进程可能随时退出或拒绝访问，缺失字段按 0 处理。
- 启用「最小化时暂停采样」后，窗口最小化期间跳过采样；恢复窗口后的下一次刷新继续采集，历史曲线不会补录最小化期间的数据。
- 耗时采集在后台串行执行，不会重复堆积并发任务；可观察集合和属性通知只在 UI 线程更新。
- WMI 查询返回脱离原生句柄的数据快照，及时释放查询资源。
- 网速通过网卡累计字节数的差值计算（**Mbps，十进制**）；磁盘速率通过 WMI 已格式化的 **bytes/s** 计数器计算（UI 以 MiB/s 为基准标为 MB/s）。
- 首次采样可能不具备网速基线，因此速度显示为零。WMI 计数器禁用时，磁盘速度可能一直为零。
- 暂停会保留当前读数并忽略尚未显示的采样结果。恢复后继续追加历史，不补录暂停期间的数据。图表横轴按采样点排列，5 秒档的 60 个点不代表 60 秒。

## 架构

```
Services/       Windows API、WMI 数据采集、进程与电源状态、偏好与开机启动
Models/         采集结果数据结构（含进程快照）
ViewModels/     UI 线程上的状态、通知、聚合与历史缓冲
Views/          WinUI XAML 页面
Controls/       趋势图、仪表盘，以及 PageHeader / SettingsCard / InfoRow / StatTile
App.xaml        Fluent 调色板、卡片与排版样式、自定义控件模板
```

## Windows 手动验收

1. 启动后观察总览：首次更新前不能复制摘要；更新后指标卡的迷你趋势图逐点增加，到所选采样点数后保持不变；四张卡片在 1200 / 780 像素断点间正确换行。
2. 在设置中切换浅色 / 深色与 Mica / 亚克力 / 纯色：卡片、图表、仪表盘、标题栏按钮颜色均清晰可读，无残留旧主题颜色。
3. 选择 5 秒档并暂停：状态点变为琥珀色、更新时间与曲线保持不变；按 F5 可单次刷新；复制摘要到记事本，核对时间、CPU、内存与网速；恢复后曲线继续更新。
4. 调整采样点数 30 → 120 → 60，确认曲线与横轴保持同步；关闭网格线 / 面积填充后图表立即变化。
5. 开启 CPU 提醒并把阈值调到当前占用以下，确认顶部出现提醒条；关闭后同一区间内不再弹出，占用回落后再次超过阈值会重新提醒。
6. 缩放窗口并退出，重新启动确认窗口尺寸被还原；开启「启动时最大化」后重启确认最大化。勾选开机启动后可在任务管理器「启动」页看到 System Monitor，取消后消失。
7. 在 CPU 和系统信息页检查多行参数，确认字段没有叠放。切回总览，确认历史未清空。
8. 打开进程页：等待首次慢速采样后列表出现进程；输入关键字筛选，切换「CPU 使用率 / 名称 / PID」排序，选中一行查看详情；点击「复制列表」粘贴到记事本核对；重启应用确认排序与筛选已恢复。
9. 把鼠标移到 CPU / 内存趋势图上：出现竖直参考线、数据点与数值气泡，移出图表后消失；在设置中关闭「鼠标悬停读数」后不再出现。
10. 打开电源页：笔记本上确认电量与充电状态随插拔电源变化；台式机显示「无电池」，电量环保持为空。系统信息页的显卡与驱动字段有内容。
